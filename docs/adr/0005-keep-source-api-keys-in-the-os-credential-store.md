# Keep Source API keys in the OS credential store

Some Sources only answer requests that carry an API key, which the user gets from their own account at that Source. Game Media Vault keeps such keys in the operating system's secure credential store (Windows Credential Manager, macOS Keychain, the Secret Service on Linux), one entry per Source under the service `game-media-vault`, shared by every vault the machine opens. A key is never written to a vault, a log, an export, a request document or an Asset's provenance. It is never passed on a command line either: the CLI reads it from standard input, so shells never keep it in their history.

A vault is meant to be copied, backed up and shared, and an API key belongs to a person's account rather than to the media a vault catalogs. Keeping keys with the vault would leak them with every copy, while the OS store protects them with the user's login and lets every vault on the machine use the same account. In the application, a key is an `ApiKey` value whose `Debug` output never shows it and which cannot be serialized. Source descriptions only say whether a needed key is stored.
